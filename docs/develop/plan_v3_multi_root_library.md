# Image Triage v3 - Multi-Root Library, Content Identity and Folder Workflow

**Status:** `[x]` complete
**Created:** 2026-11-12
**Supersedes:** the GUI parts of [`plan_v2_gui_workflow`](plan_v2_gui_workflow.md) (completed). `plan_v2_gui_workflow` remains the historical record.
**Target:** turn the local GUI into a multi-root, content-addressed photo library with folder navigation, tri-state selection, flat/tree export with optional re-rendering, a configurable tile/metadata layout, and a calibrated blur score.

---

## 1. Objective and desired outcome

The current GUI is a solid single-root browser. Version 3 turns it into the primary photo-library tool:

1. one central database and cache under the user's appdata, independent of any photo folder;
2. several watched roots scanned together, with manual add/remove;
3. photo identity, metrics, ratings and overrides bound to the image content hash, not to a path;
4. a flat tile view and a folder-tree view, switchable at any time;
5. folder-level selection with checked, unchecked and indeterminate states;
6. tile metadata chosen by the user, with the file name as the first line and the path below;
7. export flat by default, optionally preserving the folder tree, with optional JPEG re-rendering at a configurable maximum long edge and quality;
8. a blur score that is meaningful for every photo instead of being 0.0 almost everywhere;
9. a settings page that manages everything needed to run the library, shared by GUI and CLI.

The result must remain local-first, deterministic, non-destructive to originals, and testable without external services.

---

## 2. Scope, constraints and explicit non-goals

### 2.1 In scope

- Central appdata layout for the state database, cache, previews and default exports.
- Multiple watched roots in one database.
- Content-addressed photo identity with a separate location table.
- Folder tree and flat tile views, with a visible toggle.
- Tri-state folder selection and browser-local selection.
- Opt-in tile metadata fields.
- Export to a flat directory or a reconstructed folder tree.
- Optional JPEG re-rendering with a maximum long edge and quality.
- Absolute, calibrated blur score.
- Settings page for roots, exclusions, display, export, scoring and analysis settings.
- Documentation, tests, migration checks and CI.

### 2.2 Constraints

- Local-only, single-user, no authentication.
- Originals are never modified. Export only reads sources.
- Existing per-library databases are left untouched; the central database starts fresh.
- The CLI must keep working and must honour the same central configuration.
- `make fmt`, `make lint`, `make test`, `make deptry`, `mkdocs build` and the wheel/entry-point checks must pass.
- `config.yaml` and `docs/usage/config.md` remain generated by `make syncdocs`; never edit them directly.

### 2.3 Explicit non-goals

- No live filesystem watching or automatic background rescanning.
- No cloud, remote or multi-user libraries.
- No target file size in kB; the user replaced that with quality-based re-rendering.
- No RAW re-rendering; RAW files are copied or linked unchanged.
- No import of old per-library databases into the central database.
- No change to the existing scoring weights unless a concrete defect is found.
- No new heavyweight UI framework; server-rendered HTML plus the existing small JavaScript layer.

## 3. Architecture and decisions

### 3.1 Settled product decisions

| Area | Decision |
| --- | --- |
| Library roots | Several roots at once, in one central database. |
| Duplicate content | One content record per digest, with a locations table. Rating, metrics and overrides are shared. |
| Moved file | Track by digest; update the location path when the old path disappears. The rating follows the content. |
| Missing file | Mark the location unavailable; keep the content for history. Do not delete ratings immediately. |
| Changed file | Compute the new digest, create or reuse the content record, and repoint the location. |
| Existing database | Start fresh centrally; leave `<library>/.image-triage/triage.db` untouched. |
| Watching | Watched folders define the scan scope; scanning is manual. |
| Folder selection | Recursive: a folder selects itself and all subfolders. |
| Selection lifetime | Browser-local `localStorage`; no server-side shortlist. |
| Selection unit | The location, so the same image in two folders can be selected independently. |
| Duplicate display | Once per folder in folder view; one tile per location in flat view. |
| Default view | Flat tiles; folder view is one click away. |
| Folder tree | Only folders that contain photos; counts reflect the active filters. |
| Folder counts | Show matching counts under the active filters. |
| Overlapping roots | De-overlap automatically; scan the shortest root only. |
| Tile metadata | Default: name, score, rating, date. All other fields are opt-in in Settings. |
| Tile first line | File name only; path on a separate line below. |
| Filter alignment | Labels and inputs top-aligned in one filter block. |
| Export layout | Flat by default; folder tree optional. |
| Export re-render | Optional; maximum long edge in pixels plus JPEG quality, default 85. No target kB. |
| Export metadata | Keep EXIF and ICC; apply orientation before resizing. |
| Flat collision | Number suffix: `name_1.jpg`, `name_2.jpg`. |
| Export duplicate content | Once per matching location. |
| Export destination | Timestamped folder under appdata by default. |
| Preview cache | Central appdata cache keyed by digest. |
| Settings location | Central appdata config, shared by GUI and CLI; project `image-triage.yaml` remains an optional override. |
| CLI scope | All watched roots by default; `--root` narrows to one. |
| Blur score | Absolute 0..1, no dead zone; 0 = tack sharp, 1 = unusable. |
| Blur kind | Keep `blur_kind` and `blur_confidence` for real defect classification. |
| Settings page | Everything needed to run the library: roots, exclusions, display, export, scoring, analysis and blur. |

### 3.2 Central appdata layout

Use platform-appropriate directories, with environment overrides for tests and portable installs.

- Configuration: `~/.config/image-triage/config.yaml` on Linux, `~/Library/Application Support/image-triage/config.yaml` on macOS, `%APPDATA%\image-triage\config.yaml` on Windows.
- Data: `~/.local/share/image-triage/triage.db` on Linux, `~/Library/Application Support/image-triage/triage.db` on macOS, `%LOCALAPPDATA%\image-triage\triage.db` on Windows.
- Cache: `~/.cache/image-triage` on Linux, platform cache equivalents elsewhere.
- Default exports: `<data>/exports/export_YYYY-MM-DD_HH-MM`.
- Environment overrides: `IMAGE_TRIAGE_CONFIG_DIR`, `IMAGE_TRIAGE_DATA_DIR`, `IMAGE_TRIAGE_CACHE_DIR`.
- `input.db_path`, `input.cache_dir` and `input.root` remain explicit overrides for tests and single-root CLI use.

Configuration precedence:

`explicit CLI > environment > project image-triage.yaml > appdata config.yaml > defaults`.

The central config is the primary GUI configuration. The project file remains useful for development and CI. A fresh central database is created on first run; old per-library databases are never read or modified.

### 3.3 Content-addressed data model

Target schema version 3.

Core tables:

- `roots(id, path UNIQUE, label, enabled, created_at)`
- `photos(id, digest UNIQUE, phash, taken, width, height, camera_make, camera_model, gps_lat, gps_lon, event_id, group_id, score, rating, flags, model_signature, analyzed_at, created_at)`
- `photo_locations(id, photo_id, root_id, relative_path, mtime, analyzed_at, available, UNIQUE(root_id, relative_path))`
- `metrics(photo_id, ..., blur_score, ...)`
- `detections(photo_id, ...)`
- `embeddings(photo_id, ...)`
- `overrides(photo_id, ...)`
- `selections(run_id, photo_id, ...)` remains content-level for CLI selection runs.
- `photo_events(photo_id, event_id)`, `photo_groups(photo_id, group_id)` remain content-level.
- `runs`, `groups`, `events`, `jobs` keep their current shape.

Invariants:

- `photos.digest` is the content identity. One digest has one rating, one score, one metric set and one override.
- `photo_locations` is the location identity. One digest can have many locations.
- A location is unique within a root by relative path.
- A moved file updates the existing location row when the digest matches and the old path is gone.
- A changed file creates or reuses a content row and repoints the location.
- A missing file marks the location `available = 0`; the content remains while any location row exists.
- Library queries show available locations only. A content row with no available location is hidden but retained for history.
- Available content is what filters, folder counts, selection and export operate on.
- Selection runs remain content-level; GUI selection is location-level and ephemeral.

### 3.4 Multi-root scanning

- `scan_paths` returns `(root, paths)` for every enabled root after de-overlap.
- De-overlap: if root A contains root B, keep A and mark B as covered; do not scan B twice.
- Analysis computes the digest once per file and upserts content by digest, then upserts the location by `(root, relative_path)`.
- Reconciliation after a scan:
  - new path -> new location;
  - changed mtime or digest -> repoint location;
  - missing path -> mark unavailable;
  - orphaned content -> keep, hidden;
  - stale banner reports new, changed, missing and unavailable counts.
- CLI `analyze`, `scan`, `score`, `select`, `report` and `export` operate on all enabled roots by default. `--root` narrows to one root.
- Previews and GUI run outputs move to the central cache, keyed by digest and job id.

### 3.5 Library UI

- Flat view: one tile per available location. The path line shows root and relative folder.
- Folder view: a left tree with folder counts, and the selected folder's locations as tiles on the right.
- Tree behavior:
  - only folders with at least one available photo are shown;
  - counts reflect the active filters;
  - each folder row has a tri-state selection control;
  - a caret or small menu offers "Select all" and "Clear".
- Filter form:
  - labels and inputs top-aligned in one block;
  - all v2 filters retained;
  - add root and folder filters for multi-root libraries.
- Tile:
  - first line is the file name only;
  - path is a separate line below;
  - optional metadata is selected in Settings;
  - default metadata: score, rating, date.
- Sorting and pagination retain the active filters and the current view.
- The default view is flat; the view toggle is visible and persistent for the session.

### 3.6 Selection and export

- Selection is a set of location ids in `localStorage`.
- A folder control selects all descendant location ids; it is indeterminate when only some are selected.
- Export selected sends the selected location ids.
- Export filtered re-runs the current filters across every matching location, not just the visible page.
- Export modes: copy, hardlink, symlink.
- Export layout: flat by default; optional reconstructed tree using each location's root and relative path.
- Flat naming: basename; on collision append `_1`, `_2` before the extension, in deterministic order.
- Re-render:
  - optional, off by default;
  - maximum long edge in pixels, blank means no resize;
  - JPEG quality, default 85, configurable in Settings;
  - keep EXIF and ICC; apply orientation before resizing;
  - output extension `.jpg`;
  - forces copy, because a hard link or symlink cannot point at newly rendered pixels.
- Default export destination: `<data>/exports/export_YYYY-MM-DD_HH-MM`.
- Guards:
  - reject an output directory inside any watched root;
  - reject an empty selection;
  - report missing sources instead of failing the whole job;
  - report exported, skipped, re-rendered and collision-renamed counts.
- Export runs as a background job with progress and a terminal result.

### 3.7 Blur score

Current behavior reports `blur_confidence = 0.0` for sharp photos, which looks like "no data". Version 3 adds a continuous absolute score.

Proposed calibration:

- `detail` is the subject-region Laplacian variance when detections exist, otherwise the global high-percentile value.
- `blur_score = clamp(0.02 + 0.98 * (log(sharp_ref) - log(detail)) / (log(sharp_ref) - log(blur_ref)), 0, 1)`
- `sharp_ref = 120.0`, `blur_ref = 5.0` (calibrated against the sample library so sharp photo fixtures score below 0.3).
- A sharp photo lands around 0.02-0.3; a soft or blurred photo lands around 0.6-1.0.
- The score has no dead zone: every analyzed photo receives a value.
- `blur_kind` and `blur_confidence` remain for defect classification and for the existing motion/defocus gate.
- The scoring gate is unchanged: only motion or defocus with confidence >= 0.5 halves the score.
- The UI displays `blur_score`; the photo detail shows both the score and the kind/confidence.
- CSV and JSON reports include `blur_score`.

### 3.8 Settings and configuration

The Settings page manages:

- watched roots: add, remove, enable/disable, label;
- excluded directory names and patterns;
- default view and visible tile metadata fields;
- export defaults: target directory, mode, flat/tree, re-render, max long edge, JPEG quality;
- blur calibration references;
- scoring weights and rating thresholds;
- analysis toggles: YOLO, aesthetic model, embeddings, preview size, draft mode;
- selection quotas and diversity;
- danger zone: clear the central database or the cache, with confirmation.

Behavior:

- settings are written atomically to the central YAML;
- validation errors are shown inline;
- root changes are rejected while a job is active;
- analysis or blur changes show a "rescan required" hint;
- display changes apply immediately;
- the project `image-triage.yaml` remains an optional CLI override.

## 6. Risks, dependencies and open questions

### 6.1 Risks and mitigations

- **Schema migration complexity.** Mitigate with a v2 fixture test and a fresh-database test.
- **Multi-root path identity.** De-overlap and location uniqueness tests must cover nested roots and duplicate digests.
- **Folder tree performance.** Large folders may make embedded location ids heavy; use a folder-location endpoint if the DOM payload becomes a problem.
- **RAW handling.** Re-rendering only supports Pillow-readable formats; RAW is copied or linked unchanged.
- **Blur calibration.** The absolute mapping must be checked against the sample library, not only synthetic fixtures.
- **Settings validation.** Invalid paths, overlapping roots and bad numeric values must be rejected inline.
- **Old user data.** Starting fresh means old ratings are not visible centrally; document the old database location and that it is untouched.

### 6.2 Open questions

None blocking. The following assumptions are part of the plan:

- One central database serves all watched roots; there is no per-root database.
- Selection remains browser-local and is not shared between browsers.
- The central database is per OS user, not per project.
- RAW files are never re-rendered.
- The default export directory is under appdata, not the current working directory.
- The project `image-triage.yaml` remains an optional override, not the primary GUI configuration.
