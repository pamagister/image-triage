# Image Triage v6 - Photo Review, Similar Shots and Filter Presets

**Status:** `[x]` complete  
**Created:** 2026-11-17  
**Supersedes:** parts of the GUI workflow areas from v2-v5. The v5 library workbench, selection/review flow and multi-root settings remain authoritative.  
**Target:** fix settings/preset data loss, separate events from visual similarity groups, add live adjustable similarity suggestions, make page sizes remembered and shareable, streamline photo review with keyboard decisions, and polish the GUI around shared filter controls.

---

## 1. Objective and Desired Outcome

### Objective

Turn the GUI into a faster, more understandable review tool:

1. settings and filter presets can be edited, removed, saved and ranked without losing values;
2. the current library filter stays active after Apply and does not jump back to Folders;
3. events and similar-shot groups are distinguishable, and their counts reflect available photos only;
4. users can see and click similar photos directly from the detail view;
5. detail navigation follows the current filtered result across pages;
6. page sizes of 10, 20, 50, 100 and 200 are selectable and remembered;
7. similarity suggestions are adjustable live without changing stored groups;
8. decisions and ratings are immediate and documented with keyboard shortcuts.

### Desired outcome

- Editing a preset number/slider writes its actual value, not an empty `key=` field.
- At least one profile and at least one preset always remain; removal of the last one is blocked.
- Settings file saves validate before writing and roll back ordinary write failures.
- Invalid preset/profile files are not silently overwritten; saving is disabled while they are invalid.
- “Apply filters” keeps the Filters tab active and preserves root/folder/sort state.
- Event cards show only events with available photos in enabled roots.
- A “Similar shots” page lists groups with at least two available contents.
- Photo detail opens its filter context, keeps the image visible together with scrollable similar thumbnails, and offers Previous/Next across pages.
- Page size persists in `localStorage` and can be overridden per URL.
- Accept/Reject/Rating act immediately, work from the keyboard (`A`, `R`, `1-5`, arrows), and are suppressed while typing in form fields.

## 2. Scope, Constraints and Explicit Non-Goals

### 2.1 In scope

- Settings/profile/preset CRUD, ordering, activation and validation.
- Shared filter controls between the library sidebar and preset editor.
- Save/update current library filters as a preset from the library page.
- Event/group separation and availability-aware counts.
- Live perceptual-hash similarity suggestions per photo with an adjustable limit.
- Detail view layout with image plus suggestions, Previous/Next, ratings and decisions.
- Page-size control with persistence.
- Hover/focus styling for gallery tiles.
- Tests, documentation, `make fmt`, `make lint`, `make test`, `make syncdocs`, CI.

### 2.2 Constraints

- Local-first, single-user, no authentication.
- Originals are never modified or deleted.
- Stored similarity groups are not recomputed or regrouped by this plan.
- Live similarity is read-only and uses already stored perceptual hashes; it does not add model dependencies.
- Keep FastAPI + Jinja + htmx; no SPA rewrite or Node build step.
- `config.yaml` and `docs/usage/config.md` remain generated by `make syncdocs`; never edit them directly.

### 2.3 Explicit non-goals

- No semantic/subject similarity beyond stored perceptual hashes.
- No server-side change of persistent groups or ratings.
- No named selection sets.
- No automatic recovery of values already lost before this plan; backups are recommended.

## 3. Architecture and Decisions

| Area | Decision |
|---|---|
| Preset editor | Cards using the same range sliders, checkboxes, dates and status controls as the library. |
| Preset values | Native input values round-trip through `overrides_from_field_values`; old `key=value` clients remain supported. |
| Last entry guard | At least one profile and at least one preset must remain; browser alerts and server-side 400 errors block removal of the last entry. |
| Save safety | `settings_files.replace_settings_files()` stages all YAML files, replaces them atomically and restores originals on failure. |
| Invalid settings files | Settings reports the path, disables saving and refuses to overwrite invalid files. |
| Filter state | `parse_photo_query` always echoes `view`, `tab`, `page_size`, scope fields and explicit `hide_rejected=false`. |
| Page size | Sizes 10, 20, 50, 100, 200; default 50; remembered in `image-triage:page-size`; explicit URL wins. |
| Similarity endpoint | `GET /api/photo/{id}/similar?distance=...&after=...&limit=...`; bounded paging, roots-scoped, read-only. |
| Detail navigation | `photo_neighbors()` computes position/adjacent location/photo from the full filtered result with window functions. |
| Keyboard shortcuts | Left/Right navigate; A accepts, R rejects, 1-5 rate; suppressed while editing form fields. |

### 3.2 Settled product decisions

- Event counts cover available locations in enabled roots; historical/unavailable event links no longer appear as available.
- Group counts cover available contents; single-member groups remain hidden.
- Similarity search covers all active roots, not only current filters; unavailable photos are excluded.
- Identical files are labeled separately; missing hash data allows only identical-file suggestions.
- Rating overrides appear in the library and rating filters immediately; they remain soft content-level overrides.
- Decisions apply to photo content, including copies in other locations.

## 6. Dependencies, Risks and Open Questions

### 6.1 Dependencies

- Existing FastAPI, Jinja, htmx, Pillow, OpenCV, NumPy, SQLite stack.
- No new runtime dependency; geckodriver/Firefox used only for manual browser verification.

### 6.2 Risks and mitigations

| Risk | Mitigation |
|---|---|
| Already lost preset values | Cannot be reconstructed reliably; document recovery path and backups. |
| Missing perceptual hash data | Only identical-file suggestions shown; explicit “no perceptual hash” message. |
| Similarity search performance | 50k locations took ~0.27 s locally; results bounded to 24 per page with cursor paging. |
| Multi-file save crash mid-write | Atomic per-file replacement plus rollback of already replaced files; abrupt process crash not fully transactional. |
| Keyboard shortcuts conflict with typing | Shortcuts suppressed while focus is in INPUT/TEXTAREA/SELECT. |

### 6.3 Assumptions

1. Selection stays browser-local; no server-side shortlist.
2. Stored groups remain unchanged; live similarity is a separate suggestion layer.
3. Ratings/decisions are content-level soft overrides and apply to all copies.
4. The GUI remains single-user and localhost-only.

### 6.4 Open questions

1. Should semantic subject matching be added later via YOLO embeddings?
2. Should similarity results be cacheable for faster repeated slider changes?
3. Should the detail view offer “select all from this filtered page” directly?
